How to delay startup apps in Windows 11

When too many programs open the moment you sign in, your desktop gets busy before you are ready. Delay the one app that truly needs to start later, and launch task-specific groups only when the task begins.

Short answerFor one app that should run after sign-in, make a Task Scheduler task with an At log on trigger and a Delay task for interval, then set its action to Start a program. Disable any separate Startup entry for that same app so it does not launch twice. For apps you only need when you start Work or Study, keep them out of Startup and use a suko mode with launch delays where needed.

Updated October 9, 2026 · 5 minute read

Do you need a delay, or fewer startup apps?

Start with Settings → Apps → Startup. Microsoft documents that page, Task Manager and the Startup folder in its Startup applications guide. Turn off entries for programs you do not need every time you sign in. That is often simpler than delaying them.

Delay an app only when it really belongs in every sign-in session but competes with other important startup work. For example, a communication tool might be useful every morning yet can wait a minute while you unlock your computer and open the first document. An editor for a project you work on twice a week does not belong in Startup at all; launch it when you begin that project.

Delay one app after signing in

  1. Open Start, search for Task Scheduler, and select Create Task.
  2. On General, give the task a clear name. For an app whose window you want to see, keep it running in your interactive sign-in session.
  3. On Triggers, select New, choose At log on, then check Delay task for and choose an interval that fits your PC. Start small and test.
  4. On Actions, select New → Start a program and browse to the app's executable. Add arguments only if that app requires them.
  5. Save the task. Disable that app's old Startup entry if one exists, sign out and back in, and confirm it opens once after the delay.

Microsoft's LogonTrigger.Delay documentation defines the delay as the interval between user logon and task start. The Task Scheduler interface exposes it as Delay task for on a logon trigger. This does not guarantee that one app finishes loading before another; it only postpones when the task starts.

If you see no window, inspect the task's General settings and test while signed in. If nothing launches, run the task manually from Task Scheduler Library to check the executable path, then review the trigger and Conditions tab. A sleeping or powered-off PC cannot show a newly opened desktop app.

Launch a task-specific app group with suko

Suppose Work needs an editor, terminal, browser profile and chat. Opening all of them at sign-in slows every morning, including days you are not working. A suko Work mode keeps the group together and starts it when you use its hotkey. You can save where each window belongs on one or more monitors and apply the mode's volume or Do Not Disturb preference.

Set a launch delay on an app that needs another part of the setup to start first. For example, open the editor and project folder immediately, then give a slower supporting tool a short delay before it starts. The suko mode walkthrough shows app launch options, including delay controls. Test the mode with your real programs; some apps reuse an existing window while others start another instance.

  1. Create a mode named for the task and add only its apps, files, URLs or browser profile.
  2. Arrange the windows and save the layout if their positions matter.
  3. Add a delay only to an app that opens too early or requires another app to be ready.
  4. Run the mode from a clean desktop and again when some apps are open. Adjust delays based on what actually happens.

This is a different trigger from Task Scheduler's after-logon delay: a suko mode starts when you activate it or when one of its configured triggers applies. Avoid duplicate launches and fragile timing

  • Keep one owner per app: do not enable the same program in Startup, Task Scheduler and a mode unless you intentionally want repeated launch attempts.
  • Save before testing: a repeated launch can create another document window or change which existing window has focus.
  • Use the smallest delay that works: an arbitrary long wait makes the desktop feel slow without making a failing app reliable.
  • Recheck after updates: an app's executable path or startup behavior can change, so retest the task or mode when its launch stops working.

Common questions

Can Windows 11 delay one startup app without another utility?

Yes. Create a Task Scheduler task with an At log on trigger, select Delay task for, and set Start a program as its action. Disable the app's old Startup entry to avoid opening it twice.

Does a delayed startup app run at a fixed time?

No. An At log on trigger starts its delay when you sign in. Use a time-based trigger if the app should run at a particular clock time.

Can suko launch my work apps in an order?

A suko mode can launch a task's apps together and set launch delays for individual apps. Test the actual applications and adjust the delays; a delay controls start time, not when an app is fully ready.
